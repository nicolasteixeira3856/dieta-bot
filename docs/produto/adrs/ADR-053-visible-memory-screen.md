# ADR-053 — "O que a Tali sabe": the memory as a product screen

- Status: Proposed (owner direction of 07/10/2026 in `benchmark/MELHORIAS_CHAT_07_10_2026.md` § 5; accepted with the approval of A69)
- Date: 2026-10-08
- Context: `produto`
- Supersedes: partially [ADR-019](ADR-019-ferramentas-dev.md) (the dev-only tool `Memória da IA (dev)`, A23, is replaced by a product screen; the dev-only rule survives for every other tool). Complements [ADR-023](ADR-023-chat-v2-memoria-v2.md) and [ADR-029](ADR-029-fatos-temporarios-compactacao.md).

## Context

The user cannot see what the assistant remembers, nor correct or delete a fact, except through the dev tool hidden from testers. The brainstorm and both external evaluations list the invisible memory as a trust gap; the benchmark shows memory updates the user did not ask for (`replace`, `reinforce`) arriving silently.

## Decision

1. **A product screen in Config: "O que a Tali sabe".** Lists every fact with its category, slot, text, macros when any, origin (declared, recorded N days, temporary until date) and date. Actions per fact: delete, correct the text (same category and slot). A deleted fact does not return from history: compaction and digests never recreate a deleted fact (the app keeps a tombstone by fact key until the next compaction).
2. **The Chat says what it saved.** When the app applies a permanent fact from an explicit statement, the receipt line "Anotado: {fact text}" is generated by the app from the fact as stored (A64), so the user reads what the model understood.
3. **The dev tool goes.** A23 leaves the dev flavor once the product screen exists; `debug.fibrai.hide_dev_tools` keeps its meaning for any remaining dev tool.
4. **O6 stays conditional.** An onboarding screen for routines is opened only if the measurement of the Chat discovery (ADR-051) shows that day 0 is not covered; it needs its own ADR, gold and plans.

## Motivation

- The owner's reference experience let the owner read and edit the profile the bot used; Fibrai's memory must be at least that visible.
- Correction in the screen is cheaper than a conversation turn and never a model call.

## Consequences

### Positive

- Trust: what Tali knows is one tap away, with delete and correction.

### Negative

- One gold (design plan), a Config entry, Room changes for the tombstone. Accepted.

## Alternatives considered

### Keep the dev tool and expose it in prod

Rejected: it is a debug list, not a product screen, and ADR-019 forbids it.

### Only "esquece X" in the Chat

Rejected as the single way: it costs a model call and the user cannot see what exists.
